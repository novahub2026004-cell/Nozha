# نزهة — إدارة 9 فروع و10 حسابات

تطبيق واحد باللغة العربية وخط **Cairo المضمّن داخل `public/fonts`**. مدير عام واحد يتابع الفروع الـ9، ولكل فرع مدير بحساب وكلمة مرور مستقلين. الموظفون سجلات داخل النظام ولا يحتاجون حسابات دخول.

## الوظائف

- مدير الفرع: تسجيل حضور موظفي فرعه، وتسليم الروتين والجودة، ومتابعة المهام، ورفع البلاغات والصيانة والملفات والمحادثات.
- المدير العام: رؤية جميع الفروع، إدارة حسابات المديرين وكلمات المرور، إنشاء وتعديل القوائم والموظفين والمهام، تصحيح التقارير اليومية والحضور الحالي والقديم، ومراجعة سجل التعديلات.
- التقييم: الروتين 40% + الحضور 30% + أحدث جودة خلال 30 يومًا 30%. يغيّر المدير العام الأوزان من الإعدادات. البيانات الناقصة تُعرض كتقييم مبدئي أو غير كافٍ. المهام والبلاغات بحالتها الحالية تُعرض بجانب التقييم ولا تدخل في النسبة.
- فصل بيانات الفروع مُطبّق داخل قاعدة البيانات باستخدام RLS. لا يستطيع مدير فرع نقل حسابه لفرع آخر. يوجد حد 9 مديري فروع فعالين ومدير عام فعال واحد.
- إشعارات وتحديثات داخل التطبيق، وتقارير Excel وطباعة لحفظ PDF. التطبيق قابل للإضافة إلى شاشة الهاتف كـPWA ويحتاج اتصالًا بالإنترنت.

## الرفع على GitHub

1. فك الضغط وارفع **محتويات مجلد `nozha`** إلى مستودع GitHub خاص. يجب أن يكون `package.json` في جذر المستودع؛ إذا رفعت المجلد نفسه فحدده كـRoot Directory في الاستضافة.
2. لا ترفع `.env.local` أو `team-credentials.private.json`. ملف `.gitignore` يستبعدهما تلقائيًا عند استخدام Git، لكن الرفع اليدوي عبر المتصفح يستلزم عدم اختيارهما.
3. اربط المستودع باستضافة تدعم Next.js مثل Vercel. التطبيق يستخدم صفحات وخدمات على الخادم؛ GitHub هنا لحفظ الكود، وليس تشغيل التطبيق عبر GitHub Pages.

## إعداد قاعدة البيانات لأول مرة

1. أنشئ مشروع Supabase جديدًا.
2. من SQL Editor شغّل ملفات `supabase/migrations` **من `0001` حتى `0011` بالترتيب**، كل ملف منفصل ومرة واحدة فقط. يجب تشغيل `0003` منفصلًا قبل `0004` لأنّه يضيف قيمة enum.
3. انسخ `.env.example` إلى `.env.local` واملأ عنوان المشروع، المفتاح العام، ومفتاح `SUPABASE_SERVICE_ROLE_KEY` السري. لا تغيّر اسمه إلى `NEXT_PUBLIC_`.
4. ضع اسم دخول المدير العام وكلمة مرور من 12 حرفًا على الأقل في `INITIAL_ADMIN_USERNAME` و`INITIAL_ADMIN_PASSWORD`، واسمه في `INITIAL_ADMIN_NAME`.
5. عدّل أسماء الفروع والمديرين في `config/branches.example.json`. الأسماء المرفقة مثل «الفرع 01» مؤقتة وقابلة للتغيير.
6. باستخدام Node.js 22 أو أحدث شغّل:

```bash
npm ci
npm run setup:team
npm run dev
```

أمر `setup:team` ينشئ **10 حسابات فعلية في مشروع Supabase الذي ربطته**، وكلمة مرور مختلفة لكل مدير فرع. يحفظها محليًا في `team-credentials.private.json`، ولا يطبعها في سجل الطرفية. ينشئ أيضًا روتينًا ونموذج جودة ابتدائيين قابلين للتعديل. يُشغّل على قاعدة فارغة فقط. إذا كانت الحسابات موجودة بالفعل، أدِرها من داخل التطبيق ولا تعِد تشغيل الإعداد.

## نشر نسخة العميل

أضف متغيرات البيئة التالية إلى Vercel، ثم انشر المستودع:

```text
NEXT_PUBLIC_SUPABASE_URL
NEXT_PUBLIC_SUPABASE_ANON_KEY
SUPABASE_SERVICE_ROLE_KEY
NEXT_PUBLIC_DEMO_MODE=false
ENABLE_PREVIEW=false
```

مفتاح service role يستخدمه الخادم لإنشاء حسابات المديرين وتغيير كلمات مرورهم ولا يُرسل للمتصفح. لا تحتاج الاستضافة إلى متغيرات `INITIAL_ADMIN_*` بعد الإعداد المحلي. في Supabase اضبط Site URL على رابط التطبيق المنشور. اختبر الدخول بحساب المدير العام وحسابي فرعين قبل استخدام بيانات العمل الفعلية.

## تحديث مشروع موجود

إذا كنت قد طبّقت `0001` إلى `0009` مسبقًا، شغّل **`0010` ثم `0011` فقط**، وحدّث الكود والمتغيرات ثم انشر من جديد. احتفظ ببيانات المشروع. لا تشغّل `setup:team` أو `seed` على مشروع به بيانات.

## معاينة التصميم والاختبارات

للمعاينة المحلية اضبط `ENABLE_PREVIEW=true` ثم افتح `/preview`. تستخدم المعاينة نفس مكونات لوحة المتابعة مع بيانات توضيحية؛ لا تُعد حسابًا ولا تحفظ عمليات. أعد المتغير إلى `false` في نسخة العميل.

```bash
npm test
npm run build
```

اختبارات قاعدة البيانات المحلية تستخدم PostgreSQL عبر PGlite مع محاكاة هوية Supabase. تختبر فصل الفروع وتسليم التقارير والجودة وتصحيحات المدير العام. لا تُغني عن اختبار الاتصال بخدمة Supabase الفعلية بعد النشر. صور الواجهة الفعلية موجودة في `docs/screenshots`.
